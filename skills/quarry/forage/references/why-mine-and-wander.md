# Discovery before commitment

## Use when

Use a software need that might be served by an existing project rather than an assumed build decision.

## Method

Define the capability and non-negotiable constraints, then explore several plausible terms and neighbours. Separate identifying candidates from recommending adoption. Capture useful negative evidence and missing capabilities so the search informs the next decision even if no candidate fits.

## Example and record

A project may solve the core algorithm but not the operational integration, while another offers a maintained interface around a narrower algorithm. Present those as different starting points with their remaining work, not as a single unexplained winner.

## Limits and handoff

There is no obligation to find a repository to justify the search. A shortlist, a vocabulary map, or an evidence-backed decision to build a small missing piece can all be useful outcomes.
