# Make a use-specific adoption recommendation

## Use when

Use the intended deployment, required capabilities, risk tolerance, inspected revision, and evaluation evidence.

## Method

Separate capability fit, integration and migration cost, maintenance risk, licence constraints, and verification gaps. State which evidence is decisive and which remains uncertain. Recommend adoption, a bounded trial, further investigation, or rejection with conditions and a reversible next step. Use scores only when their meaning and tradeoffs are explicit.

## Example and record

A well-maintained library can still be unsuitable because it lacks a required data format. A small project may fit a low-risk internal need while requiring unacceptable support effort for a critical service. The same repository can therefore support different verdicts for different uses.

## Limits and handoff

An aggregate score is not a measurement of universal project quality. Do not convert missing evidence into either automatic trust or automatic failure.
