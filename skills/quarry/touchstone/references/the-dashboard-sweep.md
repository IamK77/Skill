# Inspect maintenance and compatibility where they matter

## Use when

Use the candidate revision, intended use, available source, release history, and trial budget.

## Method

Inspect the implementation of required capabilities, relevant tests, dependency and licence information, release or migration notes, and issue handling around the target use. Run a representative bounded trial when feasible. Record dates or revisions so maintenance claims remain attributable rather than timeless labels.

## Example and record

For a storage component, a recovery or migration trial can matter more than a general activity chart. If that trial cannot run in the available environment, state the limitation and identify the next evidence needed before adoption.

## Limits and handoff

A dashboard sweep is a source-gathering technique, not a mandatory scorecard or proof of maintainability. Do not generalise from one unresolved issue without its context.

Use the [current skill workflow](../SKILL.md) for the selected task and its completion conditions. This reference adds technique, not a separate run or mandatory stage.
