# Weight observations by their connection to the decision

## Use when

Use the claim being evaluated and the source of each supporting signal.

## Method

Prefer evidence that reaches the relevant implementation or consumer behaviour. Distinguish documentation claims, code inspection, executed trials, maintenance observations, and hearsay. Check whether several apparently independent signals repeat one source. Treat generated-looking prose or a polished dashboard as a prompt to inspect substance, not as proof of quality or fraud.

## Example and record

A large test count is less informative than a retained test exercising the required failure path. Conversely, a sparse public issue tracker may reflect a small user base rather than neglect. Record the interpretation and its uncertainty.

## Limits and handoff

No visible signal is ungameable. Avoid diagnosing authorship or intent from style, stars, activity counts, or naming alone; connect the observation to the actual adoption risk.
