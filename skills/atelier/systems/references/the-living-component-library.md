# Examples that exercise real reusable components

## Use when

Use the actual component implementation, representative consumers, supported states, and contribution conventions.

## Method

Render live examples from the same implementation consumers use. Include meaningful content and important interaction, theme, and sizing states. Make the source of examples and fixtures clear, and verify that a change reaches both the library and an affected consumer. Pair visual examples with relevant behaviour and accessibility checks rather than treating screenshots as complete evidence.

## Example and record

A menu example should expose how selection, keyboard navigation, focus return, and long labels behave where those are part of its contract. A gallery of ideal static states may miss the interaction most likely to break.

## Limits and handoff

Do not maintain a second hand-built implementation solely for documentation. Size the catalog to real reuse, and distinguish demonstrated states from unsupported combinations rather than claiming exhaustive coverage.
