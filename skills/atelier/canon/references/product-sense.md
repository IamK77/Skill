# Changing the activity a surface makes possible

## Look beyond the feature list

A product can help someone notice, decide, remember, coordinate, or express something. Choose one activity and imagine it becoming the visual subject. This can produce a different interface without adding another feature.

For a research tool, putting the answer first offers speed. Putting the evidence beside a tentative claim offers inspectability. Presenting a notebook of evolving questions offers continuity. These are different relationships with the person using the tool.

## Borrow an organising practice

Try an archive's provenance, a workshop's visible work-in-progress, a map's orientation, or a letter's address to a particular reader. Transfer the useful relation rather than decorating the existing layout with themed imagery.

## Let an inconvenient state generate an idea

An empty collection might invite a first question instead of displaying an empty card. A long-running operation might become a revisitable work item instead of a blocking modal. A failure might preserve a draft so the interruption does not erase the person's intent.

## Distinguish exploration from decision

An imagined activity is a proposal, not an inferred user requirement. Bring meaningful alternatives back to the decision owner. If one is chosen, its supported states, input modes, and failure behaviour can become concrete acceptance examples in an execution SOP.

Avoid implying that aesthetic restraint or a particular visual genre is morally superior. Judge a shipped design against its actual users and requirements; use this note to widen what the design could be.
