# Control what collaborators need to know

## An opening

Move a boundary across one responsibility and observe which knowledge crosses with it. Try a narrow attestation instead of a shared model, or a published event instead of a direct call. The experiment asks what the parties should know about one another, not merely where to put the interface file.

## Elaborate a candidate

A boundary should expose the information and capabilities needed for a meaningful relationship while keeping other decisions local where useful. Examine data ownership, error semantics, versioning, and side effects as part of the contract. An interface file alone does not prevent consumers from depending on hidden assumptions.

## A small comparison

Replace a shared mutable customer object with a narrow eligibility attestation, then with a published change event. Each moves authority and timing differently. Compare one policy change and one failure story to see which relationship the product actually wants.
