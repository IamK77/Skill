# Choose a feedback source for a specific mistake

## Use when

Use representative defects and the boundaries the project wants to protect.

## Method

Choose compiler/type feedback for expressible value and interface constraints, lint or structural rules for detectable conventions and dependency boundaries, and behavioural tests for runtime outcomes. Demonstrate a selected rule on both a violating fixture and a permitted one. Keep the command and covered files explicit.

## Example and record

A type checker may reject an omitted variant, while an import rule detects a forbidden dependency. Neither establishes that an authenticated user owns a requested record. Route that claim to a policy regression rather than stretching a static-check label.

## Limits and handoff

Adopt incrementally if existing debt would obscure the intended diagnostic. Record exclusions and do not interpret an unavailable checker as a passing result.
